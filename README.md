# دَرب | مكافآت عمّان

منصة ولاء عربية للمتاجر المحلية. تعتمد على Python وFlask وSQLite وLeaflet، وتعمل بدون Node.js أو خادم قاعدة بيانات منفصل. يحفظ التطبيق المتاجر والمشتريات والأرصدة والتحديات في قاعدة بيانات محلية.

## التشغيل

يتطلب Python 3.11 أو أحدث. اتصل بالإنترنت لتحميل الاعتماديات أول مرة ولعرض طبقة خريطة OpenStreetMap.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/flask --app app demo
.venv/bin/waitress-serve --listen=127.0.0.1:8065 --call app:create_app
```

افتح [درب محلياً](http://127.0.0.1:8065). قاعدة العرض في `instance/loyalty.sqlite`. أمر `demo` يضيف 16 متجراً افتراضياً في مواقع واقعية بعمّان ومتجراً واحداً قيد المراجعة. يمكن تشغيل الأمر مجدداً بدون مضاعفة البيانات.

| الدور | بريد العرض |
|---|---|
| عميل | `customer@darb.test` |
| تاجر | `merchant@darb.test` |
| إدارة | `admin@darb.test` |
| تاجر متاجر الجامعة | `sara@darb.test` |

كلمة مرور هذه الحسابات المحلية `DarbDemo2026!`.

## ملفات قاعدة البيانات الجاهزة

- `database/darb-demo.sqlite` نسخة مستقلة من قاعدة العرض مع الحسابات التجريبية، و16 متجراً معتمداً ومتجر قيد المراجعة، والمكافآت والتحديات.
- `database/darb-clean.sqlite` نسخة فيها كامل الجداول والفهارس والعلاقات لتشغيل فعلي ببيانات جديدة.

في تثبيت جديد، انسخ الملف المطلوب إلى `instance/loyalty.sqlite` **قبل تشغيل التطبيق**. نسخة التشغيل الحالية موجودة أصلاً بهذا المسار. إذا كان المسار يحتوي بيانات، احتفظ بنسخة احتياطية منها قبل أي استبدال وأوقف الخادم أثناء الاستعادة. بعد اختيار النسخة النظيفة، أنشئ حساباً بالأمر `.venv/bin/flask --app app create-admin admin@example.com`، ثم أضف التصنيفات من لوحة الإدارة وسجّل المتاجر الفعلية.

## تجربة الشراء والتحدي

1. من حساب العميل، انضم إلى **جولة جبل عمّان** من صفحة التحديات.
2. من نافذة ثانية، ادخل بحساب التاجر وسجّل شراء بقيمة 20 ديناراً في **رفّ وورق** لبريد العميل. استخدم رقم إيصال فريداً.
3. انسخ الرمز اليدوي إلى **تأكيد شراء** في نافذة العميل. تظهر النقاط في محفظة العميل ويدخل الشراء في سجل التاجر.
4. كرر العملية من **سوق الحارة** برقم إيصال آخر. يظهر في محفظة العميل رصيد تحدٍّ مستقل قدره 100 نقطة.
5. افتح صفحة **رفّ وورق** واستبدل مكافأة. انسخ رمزها من المحفظة وأدخله في **تسليم مكافأة** من لوحة التاجر.
6. من حساب الإدارة، افتح قسم المتاجر لاعتماد **قهوة الساحة** وجعلها تظهر في البحث والخريطة.

رمز الشراء صالح لمدة خمس دقائق ويعمل فقط لحساب العميل المرتبط بالإيصال. استخدام الكاميرا من هاتف منفصل يتطلب رابطاً يستطيع الهاتف الوصول إليه. مع استضافة HTTPS، اضبط `PUBLIC_URL` على رابط التطبيق ليُستخدم في رموز QR.

## الفحص

```bash
.venv/bin/python -m unittest discover -s tests -v
```

تستخدم الاختبارات قاعدة SQLite مؤقتة وتغطي البحث وحدود الخريطة، التحكم في الصلاحيات، التسجيل واعتماد المتاجر، انتهاء الرموز وإعادة استخدامها، احتساب التحديات، وتسابق طلبات الاستبدال.

## تشغيل على خادم

استخدم تثبيتاً نظيفاً مع مجلد `instance` قابل للكتابة على قرص دائم. اضبط `SECRET_KEY` إلى قيمة عشوائية، و`HTTPS=1` لتأمين جلسات المستخدمين، و`PUBLIC_URL` إلى عنوان HTTPS للتطبيق. شغّل Waitress خلف وكيل HTTPS وأبقِ منفذ Waitress محلياً. أنشئ حساب إدارة بأمر `.venv/bin/flask --app app create-admin admin@example.com` وأدخل كلمة المرور عند الطلب. خصص قاعدة العرض والبيانات التجريبية للتشغيل المحلي. خذ نسخاً احتياطية لقاعدة SQLite باستخدام واجهة SQLite للنسخ الاحتياطي. يعتمد العرض الحالي على مزود OpenStreetMap العام للطبقات، ويمكن ضبط مزود مناسب لحجم الزيارات في `static/app.js`.
